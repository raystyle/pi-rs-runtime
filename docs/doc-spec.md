# 项目规范文档

版本: 2026-10-12

本文规定本仓库产品文档的分类、章节、语句和资源字段。产品文档陈述当前规则与当前行为。制定经过、人员、轮次编号和测量记录写在过程文档。

关键字:

- 必须: 不这样做,文档不合格。
- 应当: 默认这样做。偏离时在「限制」写出偏离后的行为。
- 可以: 允许,不是缺省。

## 1. 两种原文

本仓库有两份原文,外加一份生成物。

| 原文 | 路径 | 装什么 | 谁维护 |
| --- | --- | --- | --- |
| 结构契约 | `scripts/ctl/data/resources.json` | 标识、种类、路径、短描述、版本钉、离线结果、册路径 | 改资源时只改这里 |
| 册 | `docs/items/<组>/<件>.md` | 该件的长文规范 | 与该件行为一起改 |
| 投影 | `scripts/ctl/data/catalog.tsv` 与 `caps.tsv` | 由结构契约生成 | 不手改。生成命令是 `scripts/gen-rctl-catalog.sh` |

实例内命令的返回面(`scripts/ctl/src/main.ts`):

- `rctl search` 返回 `desc` 的前 80 个字符(第 149 行)。
- `rctl show` 返回该条的全部字段(第 170 行)。
- `rctl docs` 返回册路径、`pin` 的前 80 个字符、`offline` 的前 90 个字符(第 211–221 行)。它不读取册的正文。

因此:实例内代理每次查询先看见三个短字段。册正文由打开册路径的人阅读。三个短字段必须自身完整,不能依赖被截掉的后半句。

## 2. 文档分类

| 文档 | 面 | 读者 | 必选内容 | 禁止 |
| --- | --- | --- | --- | --- |
| `README.md` | 产品 | 外部使用者、维护者 | 镜像是什么、如何取得、产品文档索引 | 变更经过、人员、当日实例名 |
| `docs/items/` 下各册 | 产品 | 打开册的人;实例内代理拿到的是册路径 | 第 6 节的八个标签,顺序固定 | 第 5 节左列、人员、轮次编号、过程文档链接 |
| `docs/offline.md` | 产品 | 同上 | 断网定义、分层机制、做不到的事、验证命令 | 第 5 节左列;验证只写命令和期望结果 |
| `docs/params.md` | 产品 | 同上 | 名称、类型、是否必填、默认值、约束 | 切换经过;日期只当版本的一部分 |
| `docs/install-surfaces/` | 产品 | 维护者 | 这一组的共同机制 | 逐件版本、逐件来源、逐件路径 |
| `docs/known-issues.md` | 产品 | 同上 | 当前仍成立的限制、尚未关闭的缺口 | 已经关闭的事项;第 5 节左列 |
| `AGENTS.md` 的当前规则 | 产品兼合同 | 维护用代理 | 现在必须遵守的命令、版本名、钉版规则、环境事实 | 人员、轮次、当日实例名、测量经过 |
| `PROGRESS.md` | 过程 | 维护者 | 当前工作状态 | 不复制进产品文档 |
| `docs/diary/` | 过程 | 维护者 | 当日记录 | 不复制进产品文档 |
| `docs/adr/` | 过程 | 维护者 | 背景、决定、后果 | 产品文档不链到这里;决定的结果写成规则 |
| `docs/req/` | 过程 | 维护者 | 第 7 节 | 「追踪」不复制进册或三个短字段 |
| `docs/research/` | 过程 | 维护者 | 问题、材料、结论 | 不复制进产品文档 |

`AGENTS.md` 里属于过程、应当移出产品节的内容:当前工作实例的名字、待办同步、先读进度与日记、协作邻居。版本命名、钉版、一台实例、镜像不入库,这些是当前规则,留在产品节,并且改写成现在时。

产品文档的「参见」只指向本表的产品面。过程文档之间可以互链。

## 3. 章节骨架

册采用手册页的节,不采用变更记录的节。

参照:

- 手册页把一件事写成名称、概要、说明、文件、环境、附注、参见。变更写在另外的记录里。附注写当前做不到的事,不写这件事是哪一次改出来的。
- RFC 把规范句和说明分开。说明如果只解释「当时为什么」,就不进入给代理读的正文。本仓库把这类说明放进 `docs/adr/` 与 `docs/req/` 的追踪。
- rustup 的手册讲当前安装与当前覆盖;变更清单是另一个文件。
- nixpkgs 手册的选项说明是现在的声明,讨论过程在另一套记录里。选项的短说明会进检索,所以短说明本身必须成立。

这样拆,是因为本仓库已经有两份原文。`resources.json` 的 `desc`、`pin`、`offline` 相当于手册页的名称和概要,而且会被检索截断。册相当于说明、文件、环境、附注。`catalog.tsv` 相当于生成的索引,不是第三份原文。经过、人员和日期故事相当于变更记录,放进过程面,避免检索把它们送给实例内代理。

册的八个标签,顺序固定:

1. 题头:名称、一句话用途、状态、安装组。
2. 版本。
3. 来源与安装。
4. 文件。
5. 配置。
6. 离线行为。
7. 限制。
8. 参见。

题头的状态只用:已装、参考克隆、缓存固化。

## 4. 语言

- 用现在时陈述句。主语是程序、文件、命令或规则。
- 不用「我」「我们」「你」。
- 行为写成结果:程序读哪个文件,失败时返回什么,断网时哪条命令立即结束。
- 未测量的行为写「未验证」,并写出能够判定的命令。不使用方括号状态标签。
- 日期的合法位置只有两处:版本节,以及 `pin` 字段。格式是钉名、当前值、解析日 `YYYY-MM-DD`。上游版本串里自带的日期属于版本值,可以保留。
- 产品文档不写人员、不写协作位置、不写轮次编号、不写单号。
- 同一事实只在一处写全。别处用产品面链接。

## 5. 禁用词

下表左列只允许出现在本表和附录甲的引用块里。规范正文用右列,或把该分句删掉。

| 禁用 | 改成 |
| --- | --- |
| 血泪教训、血泪坑 | 删掉这个标题。内容改写入「限制」,只留当前行为 |
| 坑与留痕 | 节名改为「限制」 |
| 坑 | 写出失败行为,或并入「限制」 |
| 留痕、留痕接受 | 删掉。需要保存的经过写入过程文档。不钉版本、无校验和,写成当前规则 |
| 实证 | 删掉。行为直接陈述。没有测量则写「未验证」 |
| 顺手 | 删掉该分句 |
| 顺带 | 删掉该分句,或另写一条当前行为 |
| 炸出 | 出现 |
| 收口 | 该句若是过程纪律,移入过程文档 |
| 落字 | 写入 |
| 口径 | 写出当前值,或写「规定」 |
| 下轮补、下轮 | 本次不安装。再次执行该组时安装 |
| 钓后人 | 删掉。写当前规则 |
| 真身 | 被包装的程序 |
| 摆设 | 无法运行 |
| 来龙去脉 | 删掉 |
| 假绿 | 把失败报告成成功 |
| 半静默 | 失败没有明确的退出状态 |
| 教训 | 删掉经过,只留规则 |
| 工位、人员名、轮次编号、评审编号 | 删掉出处。规则留下 |
| 用户裁定加日期 | 删掉这层说法。规则写入「限制」;决定的背景留在过程文档 |

出现次数会过时,不写入本规范。

## 6. 册的模板

```markdown
# <名称>

> <一句话用途> ｜ 状态:已装 ｜ 组:`<脚本> <组名>`

## 版本

<钉名> = <当前值>(解析日 YYYY-MM-DD)。升级:执行 `scripts/resolve-pins.sh`,审阅差异,再执行该组。

## 来源与安装

上游:<地址>。脚本:`<脚本>` 的 `<函数>`。

## 文件

<路径>。<入口名>。包装程序写明它执行的程序。

## 配置

<文件或变量>。没有则写「无」。

## 离线行为

支持|不支持|未验证。关闭 eth0 后,<命令> <结果>。

## 限制

<当前不支持的情况>。没有则写「无」。

## 参见

<产品文档相对链接>
```

八个标签必须按此顺序出现。可以用二级标题,也可以用粗体列表项,同一册只用一种。缺一个标签则不合格。

「离线行为」的断网定义与 `docs/offline.md` 相同:关闭 eth0 之后,域名解析和直连立即失败。册里不重复定义,只写该件的结果。

「限制」写当前边界:缺少哪个文件会怎样,哪条命令在什么条件下返回哪一个结果,哪一类目标不在本组安装。不写发现过程,不写安装脚本内部的临时补救。

### 6.1 改写结果:acp

原节在 `docs/items/tools-acp/acp.md` 第 9 行和第 14 行。原文在附录甲。改写结果:

- **离线行为**:支持协议自检。关闭 eth0 后,`acpsup --selftest claude` 完成 initialize(protocolVersion=1)和 session/new,并返回会话标识。平台 HTTP 只监听 127.0.0.1:7663。没有凭证时,提示在模型鉴权处失败。模型推理使用运行期网络,不属于离线范围。
- **限制**:codex-acp 在 session/new 时要求凭证。没有凭证时,自检只完成 initialize。容器内 terminal/kill 返回 EACCES。长时间命令由该进程自己退出,或由 `/shutdown` 结束监督进程。权限确认在 120 秒内没有应答则取消。不提供「始终允许」。平台请求没有 token 时响应 401。监督进程由 `/shutdown` 或 `--selftest` 结束。

### 6.2 改写结果:Rust 工具链

原节在 `docs/items/compilers/rust.md` 第 9 行和第 22 行。原文在附录甲。改写结果:

- **离线行为**:支持已经缓存的工具链和依赖。`/opt/cargo/config.toml` 中 `[net] offline=true` 时,获取未缓存的 crate 立即返回 not found。验证:关闭 eth0 后,在新工程执行 `cargo add <未缓存 crate>`,命令立即失败。`rustc --version` 不访问网络。依赖已经在 `/opt/cargo` registry 中的工程,`cargo build` 不访问网络。工具链和组件位于 `/opt/rustup`。未验证:windows-gnu 经由 mingw-w64 的交叉链接,以及 apple-darwin 经由 zig 的交叉链接。未验证:cargo-audit 第一次运行需要 rustsec advisory-db,断网时不可用。
- **限制**:`incus exec` 不读取 `/etc/profile.d`。`$HOME/.rustup` 不存在时,rustup 报告 no default。`~/.rustup` 和 `~/.cargo` 是指向 `/opt/rustup` 和 `/opt/cargo` 的符号链接。配置里的索引段名是 `tuna-sparse`。生效的索引由 `CRATES_INDEX` 决定,默认 `https://rsproxy.cn/index`。rust-lld 的查找同时检查 `/opt/rustup` 和 `/root/.rustup`。再次执行本组时,`rustc` 已经存在则跳过 rustup-init;配置、profile、符号链接和预热每次重写。nightly 不由本组安装。coffee-ldr 需要 nightly 时,由 bof 组执行 `rustup toolchain install nightly`。由 root 的 `~/.cargo` 安装的程序只链接二进制,其余文件见 `docs/known-issues.md`。

## 7. 需求单模板

需求单全部位于 `docs/req/`,属于过程面。它不进入 `rctl` 的返回字段。

```markdown
# REQ-NNNN <标题>

状态:draft | implemented | rejected

## 需求

R1. <现在时、可测试的陈述>
R2. <下一条>

## 验收

- R1:<命令>。期望:<结果>。
- R2:<命令>。期望:<结果>。

## 追踪

<实现位置。测量记录。日期。>
```

三条必须都在,顺序固定。

- 「需求」和「验收」使用第 4 节的语句。一条需求对应一条验收。
- 「追踪」保存实现位置、测量记录和日期。册、`desc`、`pin`、`offline`、`docs/offline.md`、`docs/known-issues.md` 不得复制「追踪」。
- 需求变成产品行为之后,产品面按第 6 节重写该行为,不粘贴需求单原文。

## 8. 资源字段

`desc`、`pin`、`offline` 是字符串(`scripts/gen-rctl-catalog.sh` 第 27–37 行)。当前校验没有长度上限。投影把三列原样写入 `catalog.tsv`(同文件第 76–80 行)。

2026-10-12 的 `resources.json` 有 495 条。`desc` 全部非空,最长 132,超过 80 字符的 14 条。`pin` 非空 84 条,空 411 条,超过 80 字符的 73 条。`offline` 非空 84 条,空 411 条,超过 90 字符的 71 条。含第 5 节禁用词的条数:`desc` 3,`pin` 20,`offline` 34。

| 字段 | 必须 | 长度 | 内容 | 禁止 |
| --- | --- | --- | --- | --- |
| `desc` | 非空 | 不超过 80 个字符,与 `slice(0, 80)` 一致 | 一个现在时名词短语,说明这件东西是什么 | 日期、链接、命令、第 5 节左列、测量经过 |
| `pin` | 无钉则为空字符串 | 非空时不超过 80 个字符 | 钉名、当前值;有解析日则写 `解析日 YYYY-MM-DD` | 升级步骤、镜像差异、日记链接、第 5 节左列 |
| `offline` | 未单列则为空字符串 | 非空时不超过 90 个字符 | 以「支持」「不支持」或「未验证」起句,再加一个行为分句 | 验证命令全文、轮次、人员、第 5 节左列 |

超过该长度的说明写入册,不写入这三个字段。`rctl show` 会返回字段全文,所以不能把超长句子留在后半段指望截断来遮住。

`caps` 的 `note` 与 `example` 也会整段返回。它们应当遵守第 4 节和第 5 节,长度不按这三列截断。

字段示例:

- `desc`:`ACP 监督进程,监听 127.0.0.1:7663`
- `pin`:`CLAUDE_ACP_VERSION=0.89.1;CODEX_ACP_VERSION=2.2.2;解析日 2026-10-11`
- `offline`:`支持自检。断网时 initialize 与 session/new 完成。推理不在离线范围内。`

## 9. 迁移顺序

没有打开次数的测量。顺序按命令实际返回的文本,而不是按估计的阅读次数。工作量:S 是一个文件里可机械替换的小节;M 是一个文件、需要逐句改写;L 是全册正文。

| 序 | 对象 | 先改的原因 | 工作量 |
| --- | --- | --- | --- |
| 1 | `desc` 中 3 条禁用词,以及 14 条超过 80 字符的 `desc` | `rctl search` 每次命中都返回这 80 个字符 | S |
| 2 | 84 条 `pin` 与 84 条 `offline` | `rctl docs` 返回两者的前缀,`rctl show` 返回全文。多数前缀今天不是完整句 | M |
| 3 | `docs/items/TEMPLATE.md` | 88 册共用节名 | S |
| 4 | `docs/items/tools-acp/acp.md`、`docs/items/compilers/rust.md` | 代理通道和编译器。第 6 节已给出这两个节的改写 | S |
| 5 | 其余 86 册的「离线行为」和「限制」 | 88 册都使用旧节名。主机侧会打开册正文 | L |
| 6 | `docs/offline.md`、`docs/known-issues.md`、`docs/params.md` | 册会链到这三篇 | M |
| 7 | `docs/install-surfaces/` 的 `index.md`、`compilers.md`、`runtimes.md`、`tools.md` | 组级导览。件级事实改完册和 JSON 后,这里只留机制 | S |
| 8 | `README.md` | 仓库入口。索引只列产品面 | S |
| 9 | `AGENTS.md` | 把当前规则和过程协作拆开 | M |

每一序改完,投影重新生成,`scripts/gen-rctl-catalog.sh --check` 必须通过。册的标签和三个短字段用第 5 节左列作检索,产品面结果必须为空。守卫命令:`bash scripts/check-doc-style.sh`。它按本规范第 5 节与第 8 节计数,与基线 `scripts/ctl/data/doc-style-baseline.json` 比对,指标只许下降。迁移批收尾时执行 `bash scripts/check-doc-style.sh --update` 刷新基线。
